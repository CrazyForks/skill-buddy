# SkillBuddy 测试建设计划

本文档记录项目长期测试建设方向。测试按风险和模块边界逐步补齐，不要求一次完成。

## 测试分层

| 测试类型 | 目标 | 重点范围 | 建议工具 |
| --- | --- | --- | --- |
| 单元测试 | 验证单个函数、类和 Adapter 的确定性行为 | 路径解析、能力声明、Skill 解析、聚合、冲突策略、状态推导 | Vitest |
| 集成测试 | 验证多个模块和文件系统协作 | Adapter + scanner、IPC + PathAccessPolicy、安装/删除/扫描闭环 | Vitest、临时目录 |
| 组件测试 | 验证 Vue 组件的状态展示和用户交互 | 只读状态、启停能力、安装目标、错误提示、确认流程 | Vitest、Vue Test Utils |
| E2E 测试 | 验证 Electron 中的完整用户流程 | 扫描、安装、编辑、删除、撤销、筛选、平台专有能力 | Playwright Electron |
| 兼容性测试 | 验证不同操作系统和文件系统行为 | Windows junction、macOS/Linux symlink、中文路径、APPDATA 重定向 | CI 虚拟机、真机 |

## 分阶段计划

### 第一阶段：单元测试

- [ ] 为所有专用 Adapter 建立独立测试文件。
- [ ] 覆盖 Adapter 工厂选择和普通平台回退行为。
- [ ] 覆盖各操作系统路径解析和环境变量覆盖。
- [ ] 覆盖平台能力声明，例如启停、读写和 project scope。
- [ ] 覆盖 Skill 名称规范化、大小写、冲突和覆盖策略。
- [ ] 覆盖用户来源、官方来源和运行态来源的聚合规则。

### 第二阶段：集成测试

- [ ] 使用临时目录模拟完整平台目录结构。
- [ ] 覆盖安装后扫描、编辑后扫描、删除后扫描的闭环。
- [ ] 覆盖 supplemental roots 与普通 user/project roots 的合并和去重。
- [ ] 覆盖只读来源不能通过 IPC 修改或删除。
- [ ] 覆盖 PathAccessPolicy 对符号链接、junction 和路径逃逸的限制。
- [ ] 覆盖多平台共享真实目录时的隔离和状态写入。

### 第三阶段：组件测试

- [ ] `canToggle=false` 时隐藏所有启停入口。
- [ ] 只读安装隐藏编辑、删除和同步写入操作。
- [ ] 批量操作只计算具备相应能力的安装目标。
- [ ] 详情页正确展示来源、作用域和未知启停状态。
- [ ] 平台操作失败时显示逐目标错误，且不会误报成功。
- [ ] 网格视图和树视图保持一致的能力判断。

### 第四阶段：E2E 测试

- [ ] 启动 Electron 后发现模拟平台和 Skill。
- [ ] 完成 Skill 安装、编辑、删除和撤销流程。
- [ ] 验证官方 Skill 只读，用户 Skill 可管理。
- [ ] 验证普通平台与专用平台的操作入口不同。
- [ ] 验证平台筛选、作用域筛选和批量操作。
- [ ] 验证应用重启后扫描结果和设置保持一致。

### 第五阶段：兼容性测试

- [ ] Windows x64/arm64：`%APPDATA%`、junction、中文和空格路径。
- [ ] macOS arm64/x64：Application Support、symlink 和应用回收站。
- [ ] Linux x64/arm64：XDG/config 路径、symlink 和桌面回收站差异。
- [ ] 验证企业环境中的用户目录和 APPDATA 重定向。
- [ ] 验证目标平台运行中安装、删除或升级时的目录变化。
- [ ] 记录无法在 CI 自动化的真机验证步骤和结果。

## 灵犀专项

- [ ] 模拟 `serverdir/user_skills`、`official_skills` 和 `target_skills`。
- [ ] 验证 Windows `%APPDATA%` 优先级和回退路径。
- [ ] 验证 `official_skills` junction/symlink 可扫描且始终只读。
- [ ] 验证用户 Skill 与官方 Skill 的大小写不敏感覆盖规则。
- [ ] 验证默认冲突拒绝和显式覆盖安装。
- [ ] 验证无法读取原生状态时展示“未知”，而不是错误显示为已启用。
- [ ] 真机确认 `disabledSkillIds` 的存储位置、格式和更新时机。
- [ ] 真机确认删除用户 Skill 后 `target_skills` 和官方版本恢复行为。
- [ ] 灵犀原生启停协议未验证前，持续禁止通用文件后缀启停。

## 完成标准

- 新增公共逻辑必须至少有单元测试。
- 跨 Adapter、文件系统或 IPC 的行为必须有集成测试。
- 用户可见的能力控制和关键交互必须有组件测试或 E2E 测试。
- 平台专有实现必须记录已验证的操作系统和版本。
- 无法自动化的兼容性验证必须保留可重复执行的检查步骤。
